# Fidelity ledger

The goal is a one-to-one recreation of the offline Bubble Tanks 3 experience. **That goal is not yet complete.** Tests protect specific recovered contracts; they do not establish that an entire playthrough or every screen is indistinguishable from Flash.

## Source priority

1. The decompiled ActionScript in `../documented-bubble-tank-3/re/bt3/export_scripts_deobf/scripts/`.
2. Verified research documents, especially `research/02-core-gameplay.md` through `05-enemies-waves-difficulty.md`.
3. The Ruffle captures in `research/screenshots/` and `research/08-visual-reference.md`.
4. Earlier exported tables and dossier summaries when they do not conflict with the source.

The imported catalog contains 93 parts, 31 avatar templates, 43 enemies, one boss, two separately recovered ally designs, and 99 wave options. Wave rules, distance conditions, roster batches, mounted geometry, and original encrypted codes are retained.

## Deliberate removals and stubs

Retired community queries, sharing/ratings, online accounts, parts-pack purchase/download, advertising/analytics, and external portal medals/stat calls do not run. Their adapters are isolated in `src/game/services/extensions.ts`. The menu uses the local library in place of unavailable online tools; obsolete Flash permission tutorials, sponsor redirects, and dead website links are omitted.

Artwork is not downloaded or bundled. Mock mode uses procedural paint, with recovered body/weapon/module timelines and projectile dimensions. Its simplified contours, highlights and animation remain distinct from the supplied original artwork.

Requested usability additions include Escape as a pause key, pausing during a crossing, persistent camera zoom from 50–150% (100% preserves the original view), player firing sounds, and synthesized mock-mode audio. The Internet Archive download guide asks the player to obtain and select their own SWF; it does not download the file automatically. Music playback retries inside user gestures after browser media suspension without replacing an otherwise-current track.

The map cycle button also accepts Enter/Space and has a screen-reader description of map position and path count.

Keyboard preview placement is an accessibility addition: activate the preview, move with arrows, and confirm/cancel with Enter/Escape. Pointer placement follows the original preview-drag flow.

The shipped allied healer chooses an ally with an invalid one-based random array index. The recreation selects a valid injured ally while retaining avatar priority; enemy healers retain their first-patient ordering.

## Recent source corrections

HUD health/weapon fills are snapshots from `_‑MO`, before field combat and cooldown updates. `_‑Ta` advances passives before infection/weaken maintenance. Secondary readiness decrements to0, then resets to-1 on a separate interface frame; this interface clock continues during crossings and freezes in pause.
- Player Rocket Launcher3015 (`_‑VG`) uses `Timer(100,10)`: first shot100ms after activation, then ten callbacks at100ms spacing, with emitters1–5 repeated and current muzzle/rotation sampled on each callback. The timer continues through jam/stun/pause. Ordinary crossing `_‑ZY → _‑1J` and avatar replacement cancel it; level-zero `_‑1E(true)` bypasses FinalPartCall. Rejected transit callbacks are consumed, not replayed after arrival. Enemy4020 remains part-clocked, retaining its six-call interval between bursts.
- Beam2017 has one maintained projectile with explicit stop events, not a two-frame expiry. Mouse release removes it even while world simulation is paused; normal crossing and replacement also stop it. Source input dispatch and tank-part Run are separate. The browser clock fixture mounts the production viewport and tests held-beam pause/release plus the continuing launcher timer at35/90FPS with both asset modes.
- Massive Cannon/shield callbacks follow authored26/25-frame timelines. Stage frames continue while pause omits effects-engine polling, so a completed frame can loop before resumed polling observes it. Polling happens after field bullets; callback-born shots wait for the next field update. Arrival `_‑4j → _‑8Y` drops all registered effect timelines/text and callbacks from both fields without firing callbacks, then promotes destination bullets/pickups/allies. The previous destination-effect retention assumption was incorrect. Generic visual effects and remaining part timelines still require independent-clock reconciliation.
- Auto Cannon5003 and Seeker Flak5004 fire at their retained target, then acquire the next target. Their first eligible call acquires without firing; equal-distance acquisition chooses the last candidate. Auto aiming uses the nearest mounted detail and rounded flight prediction. Flak's source seeker scan does not filter by enemy ownership. Orbital slots do not reset their cooldown when already full. Firing sound uses the owning field's5→0→-1 counter and only friendly projectile insertion; pause freezes that counter while wall-timed rockets can still be created. Browser-clock firing throttling was removed, matching the earlier collection/hurt separation.

- `_‑Pu.Run` checks bounds, damps initial scatter before moving, and begins attraction only after scatter speed falls below0.5 (or completion cancels scatter). Acquisition is strictly within100px, independent of class; class cubed affects attraction speed. Field `LifeBubbleCollisionDetection` runs first and collects by alpha contact or the preceding movement's `blnCollected` latch. The sub10px latch therefore grants health on the following field frame. Forced attraction is14px/frame. Collection audio uses a field-owned4→0→-1 counter; there is no browser-clock collection throttle.
- `SpawnLifeBubbles` replaces the last five with five singles when a sub50 reward has more than one five and a nonzero remainder. For rewards of at least50, its one-bubble count incorrectly uses the number of fives modulo5; pcode4011–4014 confirms this is shipped behavior, not a decompiler artifact. The recreation preserves that distribution (e.g.51 drops50;55 drops56), rather than silently substituting greedy denominations. Constructor scatter speed is rolled before rotation, and native pickup views retain rotation.
- Non-player active Run is hit timer → movement/sticky → jam → ordered parts → decoration/protection maintenance → ink/infection/weaken → boundary. Infection can kill a tank after its last shot. Stunned Run advances hit/stun/maintenance only, including its entire reset frame. Enemy boundaries exempt bosses and use Damage; ally boundaries deactivate directly despite shields/forcefields. Enemy and ally loops are separate live arrays, so newly spawned enemies run immediately. Native-art browser fixtures protect pickup contact/visibility/health phase alignment; unit tests protect actor order, reset frames, live spawn insertion and outgoing-wrapper boundary/drop behavior.
- Symbols701 (`_‑KE`, part4015) and25 (`_‑IB`, part4017) use per-part counters that freeze when Run is suppressed. The rotating gun retains mount angle and alternates100 decrements plus a separate switch frame; its ordinary firing counter pauses during its inactive phase. Suppression uses a rate1 trigger, a120-call delay, four skipped triggers between shots, and the original below-50 reset. These replace the previous tank-age modulo shortcuts. Source-backed tests establish these cadences; controlled original combat recordings are still required.

- `BTAGameWorld.Run` state2 runs interface → current field → destination field → effects → crossing movement, without `myAvatar.Run`. Boundary detection starts within state0 before its ordinary calls, so the initiation frame still runs the avatar once. `_‑0D.SpawnNewBullet` gates insertion on `_‑5d`; it does not freeze existing shots or weapon timers.

Reattachment restores enemy objects into a fresh wrapper with new collections.
