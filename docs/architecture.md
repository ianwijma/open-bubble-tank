# Architecture

## Engine choice

[PixiJS](https://pixijs.com/8.x/guides/components/application) supplies the WebGL renderer and scene graph. The game does not need a rigid-body physics engine, a tile map, or an entity framework: the recovered simulation uses authored tank parts, point-against-art collision, independent velocity axes, and frame timers. Keeping those rules in plain TypeScript avoids coupling them to a framework's physics or variable-time integration.

Next.js supplies the application shell, TypeScript build, and static delivery. Tailwind is installed through its PostCSS integration; stage-specific styling is kept in one stylesheet so original Flash coordinates can remain explicit. Pixi is imported on demand by rendered screens. No server-side game API or database is required.

## Ownership and flow

1. `AssetGate` accepts a local file or initializes procedural mock artwork.
2. `AssetPack` extracts images, sounds, vectors, font outlines, and sprite placements. It composes frozen previews and shared vector-leaf textures. It never executes ABC/ActionScript or calls retired endpoints.
3. `GameShell` owns the local profile, screen navigation, dialogs, and a `World` instance.
4. `GameViewport` owns input listeners, a fixed-step accumulator, the Pixi renderer, and cleanup. Input is cleared on blur and gameplay pauses when hidden.
5. `World.step` advances one original game frame. `weapons.ts`, `projectiles.ts`, `ai.ts`, `waves.ts`, and `tank.ts` implement separate systems. Beam contact, healer patient ownership, turret construction, and status callbacks/clocks are isolated in `beams.ts`, `healing.ts`, `turrets.ts`, and `status.ts`. Rendering and browser storage are absent from these rules.
6. `GameRenderer` positions the camera at the avatar, draws fields/entities/projectiles/pickups/effects, and updates `SwfSymbolView` display lists. `AssetPack` supplies matching animated alpha-mask hit tests.
7. React observes a revision counter, approximately ten updates per second at 50 FPS; it does not render every simulation frame.

`MainMenuMotion` belongs to each menu instance and advances on the shared `StageRuntime`. `MainMenuView` retains the supplied-SWF title and control clip trees through Settings/Credits visits; A stage-wide `MenuPointer` queries native retained geometry or procedural contours; DOM buttons retain keyboard access over the canvas. Per-frame rendering uses refs and stage subscriptions, while `GameShell` owns screen changes and the guarded overlay. A new menu instance resets its intro; closing a child pane preserves its title timeline.

Attached status marks are simulation state: their chosen part positions, rotations, variants, and replacement lifetime stay stable across frames and inactive fields. `SwfTankStatusView` consumes those choices without drawing random values or changing game rules. It holds variant frames while allowing nested clips to animate and applies the recovered infection color matrix to the complete tank view. Screen ink is an independently queued global effect; its lifetime and overlap do not belong to an avatar.

`simulation/damage.ts` owns integer coercion, weaken, shield/forcefield absorption, recursive overflow, life changes, and the player hurt-channel latch. The latch advances with tank Run frames, independent of browser audio. `simulation/degradation.ts` owns the original incremental body-loss state (debt, total and cached minimum), keeping its selection order and healing behavior separate from rendering. Player bodies remain visible; surviving enemies/allies degrade, while enemy healing restores visibility before another degradation call. Both alpha collision and `TankView` consume the resulting hidden-part set.

The active frame checks progression in the interface phase, after existing-avatar controls/HUD and before field combat. Ordinary upgrades/downgrades therefore observe the previous field frame's final health. Level-zero damage starts its escape immediately. Primary input and passive weapons use separate category passes through `tickGuns`; passive shots are born after the field's bullet loop. Primary triggers run before field combat; primary cooldowns/aim and passive firing run in the later avatar phase. HUD readouts are captured in the interface phase, so later health/counter changes cannot leak into the same displayed frame. Shared secondary readiness retains its distinct zero reset frame and advances during transit. Dialog return modes retain an in-progress crossing through upgrade choice and secondary help. Boundary detection precedes interface work; the initiating state0 frame still runs the avatar, while subsequent state2 frames run both fields without player status/passive updates. Arrival clears movement and the player shield, discards all registered effects/callbacks, and resets primary counters. The fidelity ledger identifies remaining source quirks, weapon callbacks and independent animation-clock work.

`simulation/field-runtime.ts` owns each attached field's shots, pickups, allies and pending effects, plus collection/firing sound counters. `World` retains living enemies in its field cache, discards outgoing runtime collections on arrival, and preserves the destination's already-running shots, pickups and allies. Registered visual effects/callbacks from both fields are cleared by the source global-effects lifecycle on arrival. Both fields run during transit; new bullet insertion is rejected, but existing shots and weapon clocks continue. A synchronous field context projects the actual avatar into the destination's local coordinates and restores it with `try/finally`, so damage callbacks keep avatar identity. Rendering separately adds each field's offset to its local records and retains original tank identities for animated masks. Dead enemies leave at the next field frame, and the live bullet loop processes newly appended fragments in the same frame.

`simulation/player-direction.ts` separates interface direction from acceleration and translation. It preserves the recovered heavy-tank turn helper, including exact-opposite ties, and updates aim/steering during transit without enabling movement.

`simulation/wall-timers.ts` models elapsed-millisecond Flash Timer callbacks separately from fixed-step part counters. The production viewport advances it from actual RAF elapsed time and passes zero elapsed milliseconds into each fixed stage step; deterministic callers can use `World.step(input, milliseconds)` (default20ms). The player launcher starts ten100ms callbacks; ordinary crossings and avatar replacement cancel them, while pause/jam/stun and death escape do not. Transit rejects insertion without replaying consumed callbacks. Managed Massive Cannon/shield timelines advance once per stage step even while paused, loop at their authored length, and are polled only by active world modes. Completion follows field bullets. This models source lifecycle; exact Flash Timer/event-loop delivery under stalls remains a runtime comparison boundary.

`simulation/pickups.ts` owns denomination selection, initial scatter, attraction and collection. Pickup state keeps scattering and the near-center collection latch separate from completion's forced attraction. The field performs alpha/latch collection before motion, preserves the original live-vector removal behavior, and advances its own collection sound counter after completion. Bounds deliberately consult the outgoing wrapper during transit, matching the source. `weapon-cycles.ts` stores the two special enemy firing cycles on each mounted gun, so jam/stun pauses their counters independently of visual age.

Non-player actors advance movement/sticky, jam, ordered parts, protection/effects, then ink/infection/weaken and boundary checks. A stunned entry skips movement, parts and boundary for its complete reset frame while keeping protection/effects active. Enemy and ally arrays run independently without snapshots, allowing newly spawned enemies to run immediately. Player interface/passive ordering remains separate and its remaining source differences are tracked in the fidelity ledger.

`render/tank-view.ts` paints a runtime tank independently of camera and simulation clocks. The game renderer and `TankPortrait` use it for the same current mounted-part rotations, visibility, animation pose, status and protection. The portrait owns a temporary transparent Pixi canvas above the paused field, at the original tank scale. Leaving the screen destroys that canvas and its texture store. `core/tank-info.ts` supplies source class/weapon formatting and frame-based entrance/retraction; its placements, TextField metrics and font ascent come from the HUD importer. Info does not export a reconstructed static design in place of the current pose.

`core/win-screen.ts` supplies the source preparation/fade clock independently of gameplay. `WinPanel` consumes static text/art and button frames loaded into `AssetPack.uiFrames`; it has no invented statistics. `tools/import-win-geometry.ts` preserves authored positions and alpha values while filtering the retired pack-manager promotion. The separate visual-fixture viewer mounts the production panel for browser checks. The clock records original blur-pass timing, but shared CSS blur still approximates the original repeated BitmapData filtering.

## Invariants

- Simulation units are pixels/frame, degrees, and frame counters. Do not multiply recovered constants by wall-clock delta.
- The stage is 550 × 450; rendering scales to fit without changing world dimensions.
- Health and progression are the same resource. Kills alone do not grant XP.
- The level life curve is `[50, 100, 170, 250, 400, 800, 2000]`.
- Mounted primary cooldowns are independent; secondaries share their maximum mounted rate.
- Field persistence owns living enemies and their exact runtime state. Inactive fields do not keep simulating.
- Recovered catalog designs are immutable templates. Runtime health, timers, removed carrier parts, and hidden bubbles live on `Tank` instances.
- Flash artwork is optional input. Mock mode must remain playable without a file.
- Map connections are completed traversal history, independent of grid adjacency and field generation. Each unordered pair is stored once. Cleared fields remain valid destinations.
- Camera zoom changes renderer scale and inverse pointer mapping together; simulation coordinates and the fixed HUD keep their original dimensions.

## Extending the game

- Add a part definition in the catalog, an implementation in the relevant combat/AI system, and a recovered symbol or mock view. Keep part IDs stable for code compatibility.
- Keep data importers reproducible. Derived JSON is checked in so the research repository is not a production dependency.
- `services/extensions.ts` contains typed interfaces for community tanks, accounts, parts packs, medals, platform stats, and ads. Replace the offline adapters to restore those systems without adding endpoint logic to gameplay.
- `services/profile.ts` validates versioned local JSON. The persistence boundary is replaceable; no component needs to know Flash SharedObject internals.
- `services/tank-code.ts` implements the original AES-128-ECB/PKCS7 tank format using Web Crypto's CBC primitive blockwise. It is a compatibility codec, not an account/security mechanism.
- A future renderer can consume the same `World`; a replay/test harness can call `World.step` with seeded input without a DOM.

## Asset lifetime

`Tank.age` follows active actor Run. `Tank.artAge` follows attached stage frames, including pause, control suspension and the avatar during travel. `simulation/tank-art.ts` advances artwork for the player and both attached field populations once; cached inactive fields do not advance. Native painting, part alpha tests, status/infection visual origins and forcefield mask clips use that stage age. Status durations, infection damage, weapon counters and forcefield recharge retain their active clocks. Shield film has26 frames independently of its25-frame cleanup callback; shield hits stop at16 and can finish after immunity ends. Forcefield frame jumps follow the authored1/25/35 scripts on the stage clock.

`core/protection-size.ts` preserves TankData's ordered axis-record algorithm, including ties and all-centered NaN. The browser binds `World.protectionRadius` to `AssetPack`'s transformed live Script bounds; headless callers can inject geometry, with stored-radius estimates as the default. A shield mount caches its first measured diameter, while the current hit clip retains the last mount-created diameter. `AssetPack` separately creates a fresh full-design forcefield mask pose tree and caches its initial sizing before stage advancement. Native width/height NaN assignments retain authored scale; forcefield sizing uses uniform width scale. Turret shields keep the separate gameplay-radius rule. Mock parts supply procedural raster dimensions to the same ordering rule.

The supplied SWF is held only for extraction. Projectile and pickup display lists share the same vector textures as tank views. Music fades advance on a separate stage-rate clock, including in menus and while gameplay is paused. Audio Blob URLs are owned and revoked by `AudioManager`. Pixi textures and display trees are owned by `GameRenderer`; changing files, leaving a run, and unmounting remove listeners and release rendering resources. The asset pack keeps shared raster/font/timeline caches for the current selected file and clears them when replaced.

The shell owns a reactive audio-manager instance so the viewport receives the loaded pack's audio service. Pointer/key gestures retry suspended music on the current element. Mock audio is generated locally as short PCM WAVs, including a quiet music loop, and uses the same channel limits, mute controls, and cleanup as supplied SWF audio. Protection views use shared vector leaves and a cloned design mask; changing a design rebuilds its cached tank view.

The parser was adapted from `research/swf-browser-extraction/`. Corrections made here cover matrix byte alignment and shear order, `PlaceObject3` flags, retained color transforms and removal events, shape pen origins, appended style tables and paint layers, joined fill boundaries, normalized SVG view boxes, font outlines/advances, and masked sprite composition. Matrix semantics were cross-checked against [FFDec's input reader](https://github.com/jindrapetrik/jpexs-decompiler/blob/master/libsrc/ffdec_lib/src/com/jpexs/decompiler/flash/SWFInputStream.java) and [affine transform implementation](https://github.com/jindrapetrik/jpexs-decompiler/blob/master/libsrc/ffdec_lib/src/com/jpexs/decompiler/flash/exporters/commonshape/Matrix.java).

Morph placements retain their unsigned 16-bit ratio. `morphShapeAtRatio` resolves geometry, bounds, colors, gradient matrices/stops/focal values, and line widths; previews and collision use the same resolved geometry as live views. `morph-raster.ts` rasterizes generated leaf paths synchronously with Canvas2D so frame changes do not wait for image decoding. Its recent-raster cache is limited to eight million pixels. Live morph textures are reference counted by `GameRenderer` and released when their last view changes ratio or is destroyed; static vector leaves remain shared for the run. Morph structure and edge pairing were cross-checked against [FFDec's morph implementation](https://github.com/jindrapetrik/jpexs-decompiler/blob/master/libsrc/ffdec_lib/src/com/jpexs/decompiler/flash/tags/base/MorphShapeTag.java).

`tools/visual-fixtures.ts` builds a separate development viewer with deterministic world snapshots. It uses the production asset pack, simulation, and renderer; native SWF loading remains local. Browser tests compare contact masks and construction states there without adding debug routes or globals to the shipped application.

`simulation/editor-selection.ts` contains pure creator operations: ordered additive selections, faded twin membership, marquee sampling, transforms, ordering, and unlink/delete behavior. `TankCreator` owns pointer capture, transient drag snapshots, drawing, and the undo history. Selection and faded state are never exported as tank data. Browser coverage verifies the exported geometry after actual pointer interactions in both asset modes.

`simulation/editor-drag.ts` advances a creator drag one pointer event at a time. It owns per-part pointer sides, the first-move reference offset, the axis lock, merge/delete decisions, and new mirrored twin insertion. Each advance returns new parts and selection state without mutating its input. The component retains the source's axis-lock flag across gestures, records one undo entry per completed drag, and restores the starting design/selection on pointer cancellation.

`simulation/editor-placement.ts` creates transient preview geometry, applies the three-pixel axis snap, and filters each dropped member against the design bounds. Palette choice, the in-progress preview gesture, and selection of placed parts are separate editor states. The browser component owns pointer capture and the keyboard alternative; dropping an object commits one design change without selecting it. Part radii come from authored symbol bounds, excluding the raster padding used for antialiasing.

`tools/reference-player.ts` serves a separate loopback-only original SWF viewer with development dependency Ruffle 0.7.1. It shares the SWF decompressor, serves WASM with the correct MIME type, and accepts a browser-local file or explicit `BT3_SWF_FILE`. `reference-browser.ts` owns a headless Chrome/CDP instance with the stack size this movie needs; `reference-input.ts` uses Node Playwright for native coordinate input and stage captures. Ruffle is never imported by `src` or included in the Next.js output. The optional original-runtime smoke test is enabled with `BT3_REFERENCE=1`; it complements simulation tests rather than establishing whole-game parity.

`simulation/editor-palette.ts` owns affordability, unlock state, source row ordering, and default selection independently of placement. Affordability checks one object; symmetry and final design validity are handled by placement and save validation. An unaffordable unlocked row is dimmed but remains selectable.

`render/creator-artwork.ts` reuses `SwfSymbolView` in one offscreen Pixi renderer, copying its transparent frame into the creator's design and preview canvases. Each placed part owns its own timeline birth frame; moving/scaling/selecting it does not recreate the clip. Dropping transfers draft views into the design so their animation continues. The frame clock follows the selected FPS, stops advancing while hidden, and stays outside React state. Pointer alpha tests consume each part's retained visible pose. Class measurement and saved designs continue to use their separate static snapshot and numerical geometry.

`render/swf-textures.ts` owns leaf textures and reference-counted morph textures for both the game and creator renderers. Each renderer has its own store and releases it with its display trees. No animation frame atlas is generated, and closing the creator cancels its frame callback and destroys its offscreen WebGL resources.

`assets/clip-timeline.ts` runs the recovered stop, jump, rounded-random, and Y-branch actions. `assets/swf-clip.ts` owns the retained child tree and advances every elapsed stage frame, including child construction/removal while a parent is stopped. It has no DOM or Pixi dependency. `SwfSymbolView.updatePose` paints that tree; collision reads the same placements, masks, and morph ratios through `AssetPack.hitClip`.

`assets/glow-kernel.ts` and `assets/swf-color-transform.ts` hold numeric filter rules independently of Pixi. `SwfSymbolView` retains each placement's ordered glow filters, isolates authored bitmap-cache boundaries, and applies accumulated color after a filtered capture. Unfiltered branches pass color to their leaves. Embedding views supply runtime/parent alpha explicitly so Pixi ancestors do not attenuate the capture. `SwfGlowFilter` owns the repeated horizontal/vertical GPU passes and pooled scratch textures; `SwfColorFilter` applies the final bitmap transform. Contact and Script bounds retain their separate geometry. The development-only byte-image oracle and gallery test the rendering without entering the shipped game bundle.

`AssetPack.partClip` caches poses in a weak map keyed by runtime tank and resets them when its design changes. Each part has a stable private random stream derived from the tank/instance key, so repeated rendering or collision queries do not reroll animation or consume gameplay randomness. Creator clips use their own retained instances and normal random draws; the forcefield's cloned silhouette also owns independent instances. Numeric frame actions are generated from complete recognized source methods. Unsupported classes are reported, and importing fails if an unsupported frame method becomes reachable from a catalog part.

`core/minimap.ts` holds the imported layout and the compact/large/hidden state helpers. `render/minimap-view.ts` owns the native map shell, retained dot clips, traversal graphics, and clipping; it sits outside the world camera transform. Entries detach before an authored frame swap so replacing `map_mc` cannot destroy retained traversal artwork. The mock renderer follows the same control cycle and spacing. `WorldMap` supplies only the accessible cycle button and a screen-reader description; opening the map does not create a dialog or pause the simulation.

`core/hud.ts` owns health/fire idle clocks and easing in original simulation frames, ordered primary grouping, and fill calculations. `render/hud-view.ts` owns the native life/fire clip trees and their dynamic device-text children; mock mode draws the corresponding simple geometry. Both stay outside the camera transform. `GameHud` retains accessible health text and interactive controls, without React updates or CSS transitions driving the bar animation. `tools/import-hud-geometry.ts` imports only numerical origins, layout heights, and TextField metrics from the source SWF; artwork remains browser-local.

`core/edit-slider.ts` advances the source's distance-scaled entrance/retraction in simulation frames. Completion and field attachment trigger it; a settled tab reflows when the map changes size. `render/edit-slider-view.ts` paints the three native variants, including static text leaves. `EditTankControl` reads the model to move its transparent native-button bounds without React frame updates. Its DOM disabled state follows the model; React does not hold a conflicting fixed disabled prop. Clicking opens the original confirmation, then same-level replacement choices. Editing or selecting a replacement rebuilds the current progression slot at its initial health; canceling the creator resumes the run.

`core/tutorial.ts` selects a stopped caption frame using the unique-field count before attachment increments it. Every attachment, including a revisit, replaces the destination's guide. `render/field-captions.ts` retains the original static text/logo clip for each active field, below tanks, with no field-radius scaling. The field camera moves it through crossings; pausing does not remove the artwork. `tools/import-tutorial-art.ts` imports frame IDs, numerical positions and decoded fallback text. The original glyphs, colors and font outlines come from the supplied SWF. Mock mode spells out the separate W and mouse glyphs in readable fallback text.

`core/field-visit.ts` models the per-attachment completion latch independently of cached `Field.cleared`. `World` owns one current visit and a fresh destination visit during transit, checking both in source order and transferring the latch on arrival. Empty revisits increment completion statistics once per attachment without adding duplicate map paths. The initial wrapper is special; attaching home again is an ordinary visit.

`World.rebuildPlayer` owns the replacement-only secondary-help trigger and early seen latch. `GameShell` persists that event in the validated local profile; initial saved-avatar construction does not trigger it. A dedicated world mode freezes simulation while `SecondaryHelpPanel` displays the original static artwork and button frames loaded by `AssetPack.uiFrames`. Its generated placement data shares the HUD importer; the regular modal scrim is disabled so the authored white veil remains intact.

`core/tactical-hud.ts` holds fixed-stage snapshots for Radar, Health Readout and allied health. Their clocks differ: the interface updates ally rings through travel, while avatar passive parts retain their last snapshot until active again. Jam clears passive output and stun retains it. `render/tactical-hud-view.ts` paints native116/1999/2194 clips outside the camera, overwriting enemy fill scale and preserving source widths/heights. Reused clip trees keep stable textures; obsolete indicators are destroyed. `GameHud` exposes readout counts to assistive technology. Browser settings feed the simulation's numerical view zoom without DOM dependencies.

`core/target-lock.ts` defines the disabled parts-pack targeting boundary. No shipped part registers locks, and base Q input does not alter homing or auto-cannon targeting. A future pack can supply its own controller; World invokes cycle, preserved-capacity field reset, and zero-capacity avatar-replacement reset hooks. Lock-on projectile artwork alone does not establish an available weapon or its part ID.

Apocalypse calls the source's control-suspension state, separate from a normal pause or field crossing. `World` continues collapse/effect clocks while leaving the HUD snapshots and idle/edit motion frozen. Enemy Health Readout removes bars on entry; radar may persist. Editing is unavailable during collapse. The deterministic native fixture compares complete HUD pixels across20 effect frames so a renderer or clock regression cannot silently reintroduce motion.

`simulation/effects.ts` maps projectile callbacks to source effect identities independently of damage. `tools/import-effect-art.ts` regenerates their symbol IDs and frame counts without exporting artwork. Each field owns an effect request queue, flushed after its combat, pickups and completion checks. Registered effects belong to the outgoing engine layer until field promotion; destination requests retain their supplied local coordinates, matching the shared source engine. Arrival clears registered clips and callbacks. Effect ages advance on the stage clock even while gameplay is paused, while engine polling removes clips only on active gameplay/collapse frames. Massive Cannon/shield completion callbacks retain their separate managed timelines.

`render/combat-effects-view.ts` owns lower, upper and screen native effect containers and shared-texture MovieClip trees. The empty rocket-trail `line_mc` receives its dynamic two-pixel segment; the surrounding authored timeline supplies its 25-frame fade. Mock mode draws the same segment with a procedural fade and uses simple rings for the other source-defined effects. Ordinary damage/death and area damage do not independently create visual effects. Native artwork remains runtime SWF input, including all 12 newly reachable effect roots.

`simulation/projectile-contact.ts` handles the base current/backward-half-step mask tests and Massive Cannon's cardinal width samples before movement. It retains the friendly enemy-layer gate and source hit-memory behavior. Collision callbacks run before direct damage and can create effects, pickups or area damage independently. `tools/import-projectile-flags.ts` recovers constructor flags through source inheritance into `data/projectile-flags.json`; acquisition and area cleanup use those flags instead of inferring behavior from projectile kind. `simulation/bubble-buster.ts` stores only the copied movement vector in `Projectile.deflected`, modeling base Run state2. Subtype aiming/contact/fuse polls stop, while retained stage artwork continues. Movement precedes the virtual wall check, which is skipped for stopped turrets (the shipped live `_‑PJ=false` case). Beams never expire at this boundary, ricochets expire without bouncing or reporting a miss, and Apocalypse uses the stroke-inclusive background radius425.25 rather than its fill radius423.75. `assets/projectile-bounds.ts` composes native leaf transforms into field-coordinate Script AABBs independently of raster painting. `simulation/projectile-boundary.ts` centralizes the source virtual `IsOutsideOfBubble` dispatch and session-local friendly/enemy missed-shot counters. `simulation/mines.ts` separates stationary mines and seeker-mine contact/scatter/arming/homing from ordinary projectile motion. A mine stores its last movement vector for source half-step contact. `projectile-timelines.ts` owns weakly keyed retained `SwfClip` trees and advances roots and children on the independent stage clock, including pause and deflection. `mine-timelines.ts` retains a compatibility export. `Projectile.artPose` supplies the same placements to drawing, pixel contact and Script bounds; `artFrame` exposes the root frame for source polling. `tools/import-projectile-clips.ts` imports only numerical display-list metadata for seven projectile roots and their reachable clips. `simulation/mine-layers.ts` stores each mounted gun's raw seeker references or ordinary `{mc,x,y}` wrappers. `starburst.ts`, `spinner.ts`, `repulsor.ts`, `sapper.ts` and `avatar-seeker.ts` isolate the subclasses whose phases differ from base movement/contact. `create-projectile.ts` supplies fresh base state for helper shots. Camera zoom does not change these simulation distances.

`core/tank-identity.ts` retains exact supplied/imported encrypted tank-code identity for source roster lookup. `FieldRuntime.enemyRemovals` separates the immediate death callback/total-kill count from removal-time archetype counters and medal checks.
